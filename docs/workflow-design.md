# 对话流程与分支设计

## 整体流程

```
用户输入
  │
  ▼
问题分类 LLM ──► 输出: consulting / complaint / tech_support / chitchat / unknown
  │
  ├── consulting (产品咨询)
  │     ├── 商品信息提取 LLM (提取 product_name)
  │     ├── 知识检索 1 (产品知识库)
  │     ├── QUERY_STOCK (库存MCP)
  │     └── 产品咨询回答 LLM
  │
  ├── logistics (物流咨询) — 实际归入 consulting 分支
  │     ├── 参数提取器 (提取 order_number，支持订单号/运单号)
  │     ├── QUERY_LOGISTICS (物流MCP)
  │     └── 物流咨询回答 LLM
  │
  ├── policy (店铺政策) — 归入 consulting 分支
  │     ├── 知识检索 3
  │     └── 店铺政策回答 LLM
  │
  ├── promotion (促销活动) — 归入 consulting 分支
  │     ├── 知识检索 4
  │     └── 促销活动回答 LLM
  │
  ├── complaint (投诉处理)
  │     ├── 知识检索 5
  │     └── 投诉回答 LLM
  │
  ├── tech_support (技术支持)
  │     ├── 知识检索 6 (维修手册)
  │     └── 技术支持回答 LLM
  │
  ├── chitchat (闲聊)
  │     └── 闲聊回答 LLM
  │
  └── unknown (兜底澄清)
        └── 直接回复 (兜底文案)
```

## 意图分类设计

### 分类体系（5类）

| 类别 | 关键词/特征 | 示例 |
|------|-----------|------|
| consulting | 产品名、价格、参数、库存、订单号、运单号、退换货、保修、发票、活动、会员 | "RTX5080多少钱"、"订单HP20240901001到哪了" |
| complaint | 坏了、投诉、差评、退款、质量问题、发错货 | "刚买的耳机坏了怎么换" |
| tech_support | 开不了机、连不上、充电慢、蓝屏、故障、怎么办 | "手机开不了机怎么办" |
| chitchat | 你好、你是谁、谢谢、天气、无关话题 | "你好呀"、"你是谁" |
| unknown | 语义不完整、与店铺无关、乱码 | "我想咨询一下"、"帮我订个外卖" |

### 分类边界规则

- **询问政策规则** → 店铺政策（consulting分支），如"拆封了还能退货吗"
- **表达不满/要求处理** → 投诉（complaint），如"刚买的就坏了"
- **会员/积分/优惠券** → 促销活动（consulting分支）
- **故障现象+怎么办** → 技术支持（tech_support）
- **与店铺无关的请求** → 兜底（unknown），如"帮我订个外卖"

## 各分支回答规则

### 产品咨询回答
- 结合知识库产品参数 + MCP实时库存数据
- 用户未问库存时，不主动提及库存
- 用户问发货时间时，结合库存状态回答
- 多子问题时逐一回答

### 物流咨询回答
- 通过订单号或运单号查询物流状态
- 回答包含：快递商、当前状态、最新位置、时间
- 用户同时问产品信息时，一并回应

### 投诉回答
- 先安抚情绪，再基于知识库给出解决方案
- 严格约束"仅根据知识库回答，不知道就说需要联系人工"
- 不编造政策

### 技术支持回答
- 纯RAG检索维修手册，优先匹配故障现象
- 给出分步解决方案
- 无法解决时引导人工

### 闲聊回答
- 人格化设定，简短回应
- 适时引导回业务场景

### 兜底回答
- 澄清用户意图，引导提供更多信息
- 对于无关请求，礼貌说明服务范围

## 对话记忆机制

- 每个回答LLM节点开启对话记忆
- 记忆窗口：最近5轮对话
- 用于多轮对话中保持上下文（如用户先问产品再问库存）
